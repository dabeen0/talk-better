# Dutch Pay Manager (더치페이 매니저)

> 외부 API나 별도 백엔드 서버 없이 순수 프론트엔드 웹 기술(HTML, CSS, JavaScript)만으로 구현한 모임별 차등 정산 및 최소 송금 경로 계산 웹 애플리케이션입니다.

## 1. 프로젝트 개요 및 기획 배경

### 1.1 기존 정산 방식의 문제점

기존 메신저나 간편 송금 앱의 더치페이 기능은 전체 금액을 인원수로 나누는 단순 $1/N$ 방식에 머물러 있습니다. 이로 인해 실생활 모임에서는 다음과 같은 문제가 발생합니다.

* **불합리한 차등 분배:** 술을 마시지 않은 인원이나 2차부터 중간 합류한 인원까지 동일한 금액을 부담해야 하는 문제

* **불필요한 송금 횟수 증대:** 1차 식사, 2차 카페, 3차 택시비 등 각 차수마다 결제자가 다를 경우 참여자 간 주고받아야 하는 송금 건수가 기하급수적으로 늘어나는 문제

### 1.2 개발 목표

본 프로젝트는 이러한 문제를 해결하기 위해 **메뉴(항목)별 참여자 개별 지정 기능**과 **그리디(Greedy) 알고리즘 기반의 최소 송금 경로 산출 로직**을 구현하였습니다. 또한, 별도의 백엔드 서버 유지 비용이나 데이터베이스 구축 없이 누구나 Web 브라우저만으로 즉시 이용 가능한 **서버리스 정적 웹 애플리케이션**으로 완성하였습니다.

## 2. 주요 기능 및 알고리즘

### 2.1 항목별 참여자 개별 지정 및 차등 정산

* 지출 항목(영수증 내역)마다 선결제자(누가 냈는가)와 실제 참여자(누가 함께 이용했는가)를 개별 선택합니다.

* 각 항목의 결제 금액은 해당 항목에 체크된 인원들에게만 $1/n$로 분할 계산되어 individual share에 반영됩니다.

### 2.2 그리디(Greedy) 알고리즘 기반 최소 송금 횟수 최적화

참여자 $i$의 총 결제 금액을 $P_i$, 총 부담 금액을 $S_i$라 할 때, 순 순수 정산액(Net Balance) $B_i$는 다음과 같습니다.

$$
B_i = P_i - S_i
$$

* $B_i > 0$: 받아야 할 금액이 있는 채권자 (Creditor)

* $B_i < 0$: 보내야 할 금액이 있는 채무자 (Debtor)

채무자 집단과 채권자 집단을 각각 절댓값 기준 내림차순으로 정렬한 뒤, 가장 많이 보내야 하는 사람과 가장 많이 받아야 하는 사람을 교차 매칭하여 상계 처리합니다. 이를 통해 $N$명의 참여자 간 발생할 수 있는 최대 $N(N-1)$회의 송금 건수를 최악의 경우에도 최대 $N-1$회 이하로 대폭 단축시킵니다.

### 2.3 10원 미만 자투리 금액 처리 및 오차 보정

* `1원 단위 정확히 계산`과 `10원 단위 올림` 옵션을 제공합니다.

* 나누어떨어지지 않는 소수점/원 단위 부동소수점 오차는 총 지출 합계와 총 부담 합계가 항상 일치하도록 최다 선결제자 항목에서 자동 보정되도록 로직을 작성했습니다.

### 2.4 무상태(Stateless) URL 인코딩 데이터 공유

* 서버 DB를 사용하지 않고 정산 내역을 타인에게 전달할 수 있도록, 전체 상태 객체(JSON)를 Base64 문자열로 직렬화하여 URL 파라미터(`?data=...`)로 구성합니다.

* 카카오톡 메신저 전송용 서식(지출 항목, 최소 송금 가이드, 입금 계좌) 텍스트 자동 복사 기능을 지원합니다.

### 2.5 반응형 UI 및 모바일 가로 잘림 방지

* 모바일 환경(360px~375px 초소형 해상도)에서도 레이아웃 깨짐이나 버튼 오버플로우가 발생하지 않도록 CSS Flexbox와 Grid 기반 반응형 설계를 적용했습니다.

* `localStorage` 연동을 통해 새로고침 및 재접속 시 이전 정산 내역이 자동 유지됩니다.

## 3. 기술 스택 및 아키텍처 (Serverless Architecture)

### 3.1 기술 스택

| 구분 | 사용 기술 | 비고 | 
| ----- | ----- | ----- | 
| **Frontend** | HTML5, CSS3, Vanilla JavaScript (ES6+) | 외부 프레임워크(React/Vue) 없이 순수 자바스크립트로 구현 | 
| **Styling** | Tailwind CSS (CDN), FontAwesome Icons | 웹 응답성 및 UI 시각적 직관성 확보 | 
| **Storage** | Web Storage API (`localStorage`), URL Query | 데이터 영속성 및 상태 전송 | 
| **Hosting** | GitHub Pages | 정적 웹 호스팅 서비스 | 

### 3.2 서버 구조 및 배포 방식

```
[사용자 브라우저 (Client)]
   ├── 1. DOM 조작 및 입력 받기
   ├── 2. JavaScript 엔진 내 차등 정산 & 최소 송금 연산
   ├── 3. JSON ⇄ Base64 직렬화 (URL 파라미터 생성)
   └── 4. LocalStorage 데이터 저장
        ▲
        │ Static Web Asset 제공 (HTML / CSS / JS)
        ▼
[GitHub Pages CDN Server (Serverless)]
```

* **Zero-Backend 구조:** 백엔드 API 서버나 RDBMS를 구축하지 않아 서버 유지 비용이 0원이며, 서버 다운이나 트래픽 과부하 우려가 없습니다.

* **보안성 및 개인정보 보호:** 모임 참여자의 이름, 계좌번호, 결제 금액 등 민감 정보가 중앙 서버로 수집되지 않고 사용자 기기 내부 메모리 및 공유 URL 상에서만 전달되므로 개인정보 누출 위험이 없습니다.
